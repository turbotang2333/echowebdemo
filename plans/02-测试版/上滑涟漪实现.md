# 测试版 · 上滑涟漪实现

每次上滑成功推进剧情，画面有一道横向水波纹从下向上掠过 ——
强化"剧情向前"的反馈，又不抢戏。本文档记录**旧版（commit `005c2fe`）那版被认为"感受好"的实现**，
以及它好在哪。以后改动若手感跑偏，按本文档照搬参数。

---

## 目标体验（一句话）

> 一条**淡淡的**水波纹掠过画面 —— 看得见、不抢戏。
> 氛围色、立绘、特效、文字 **全程清晰可读**，涟漪只是"附加的折射镜"。

---

## 旧版为什么感受好

按重要性排序：

1. **被扭曲的"图"细节克制**
   旧版只克隆 **`.screen-bg` + `.character-layer`** 两层做快照来扭曲。
   `atmo-env / atmo-emotion`（氛围色）、`fx-dominant-*`（粒子/光柱）、
   `fx-burst-layer`（白闪/雾/灯笼）**全都不在快照里**。
   → 扭曲的对象本身细节就少，画面看着"淡"。

2. **波带外是实时舞台**
   mask 在波带之外是 `transparent`，露出底下真实 `#stage` 的原貌
   （含所有正在运行的氛围色、粒子、特效、文字气泡）。
   → 视觉延续感强；带子内外都是"当下画面"，没有冻结感。

3. **低频噪声 = 大波浪而不是高频抖**
   `feTurbulence baseFrequency="0.006"` 单值，波长约 1/0.006 ≈ **166 px**。
   屏幕上是"几个大波在晃"，不是"几个像素一个的碎抖"。

4. **模糊够柔，边界是水不是错位**
   `feGaussianBlur stdDeviation="2.5"` 把噪声边缘磨软。
   位移看起来像**水的折射**，不像马赛克/像素错位。

5. **位移强度克制**
   `feDisplacementMap.scale` 钟形曲线 `6 → 24 → 6`。
   峰值 24 px 在常见 ~900 px 高的屏上 ≈ **2.7% 屏高** —— 看得见，不喧宾夺主。

6. **节奏匹配**
   总时长 **2000 ms** + `easeInOutSine` 让波带在 t ≈ 0.5 时正好掠过屏幕中央，
   `scale` 的钟形峰值也在 t = 0.5。**视觉冲击点和波带位置同步在画面正中**。

7. **同心圆点缀，独立轻量**
   4 个白圈从屏底向外扩散，独立 DOM 节点（`.wave-ring`），
   不进 SVG filter 管道，性能成本极低，但提供"水波顶"的高亮暗示。

---

## 性能为什么轻

旧版**没卡**，根本原因是 filter 跑在**静态克隆**上：

- 克隆出来的快照是一张**不再变**的图。浏览器可以**光栅化一次后缓存**，每帧只重算最后一步 displacement → GPU 友好。
- 快照里**没有 canvas**（`fx-canvas` 不在克隆范围内）。
- 快照里**没有 mix-blend-mode**（`atmo-env / atmo-emotion` 都没克进来）。
- 波带本身用 **CSS `mask-image: linear-gradient(...)`**，GPU 直通路径，比 SVG mask 便宜得多。
- 真实 `#stage` 里的 canvas 粒子、atmo 染色照常跑，但**不经过 filter**。

**反面：什么会让它卡**
把 filter 挂到「含 canvas + 含 mix-blend-mode + 内容每帧在变」的容器上，
浏览器会强制每帧重新光栅化整层再走完整 filter 管道，多数还会退到软光栅。

## 照搬参数表

| 维度 | 参数 | 数值 |
|---|---|---|
| 总时长 | `DURATION` | `2000` ms |
| 噪声 | `feTurbulence` baseFrequency | `0.006`（X/Y 同频） |
|  | numOctaves | `1` |
|  | seed | `3` |
|  | type | `fractalNoise` |
| 柔化 | `feGaussianBlur` stdDeviation | `2.5` |
| 位移 | `feDisplacementMap.scale` 曲线 | `6 + Math.sin(t * Math.PI) * 18`（钟形 6→24→6） |
| filter region | x/y/width/height | `-10% / -10% / 120% / 120%` |
| 波带 | center 轨迹 | `-25%` → `+125%`（`easeInOutSine`） |
|  | halfWidth | `16`（实心区 ±16% 屏高） |
|  | fade | `14`（上下软边各 14% 屏高） |
|  | 实现方式 | CSS `mask-image: linear-gradient(to top, ...)` |
| 同心圆 | 数量 | 4 |
|  | delays | `[0, 250, 500, 760]` ms |
|  | 最大尺寸 | `max(innerWidth, innerHeight) * 2.2` px |
|  | size 缓动 | `easeOut`（`1 - (1-t)^3`） |
|  | opacity 曲线 | 三段：升 (0→20%) → 平 (20→65%) → 降 (65→100%)，峰值 `0.28` |

## 实现要点（必须照搬的几条）

1. **挂载位置**：快照与同心圆都插入到 `#narration-zone` **之前** —— 这样 z-index 在视觉层之上、文字之下。
2. **快照内容**：
   - `.screen.active .screen-bg`（带 `::after` 暗角一起）
   - `#character-layer`（深克隆，**移除 id**，含 `[id]` 后代）
   - **就这两个，不要再多加**。多加一层就回到"卡 + 抢戏"的坑。
3. **mask 起点**：插入前先 `setBand(snapshot, -40, 16, 12)` —— 波带在屏外，第一帧零可见。
4. **双 `await raf()`** 后再开始 tween：确保浏览器把初始态提交渲染，避免直接跳变。
5. **同心圆 host** (`.wave-rings`) 与快照并列同层，不要套到快照内 —— 圆环不需要被 filter 扭曲。

---

## 不要做的事

- 不要把 filter 挂在含 `canvas` 的活容器上。
- 不要把 filter 挂在含 `mix-blend-mode` 的活容器上。
- 不要把 `baseFrequency` 抬到 `0.01` 以上 —— 看着像高频抖动。
- 不要把 `stdDeviation` 降到 `2` 以下 —— 边界变硬像错位。
- 不要把 `feDisplacementMap.scale` 峰值抬到 `30+` —— 喧宾夺主。
- 不要把波带掠过时长缩短到 `1500ms` 以下 —— 太急，"水波"变"刷子"。

## 已知折中

旧版的代价：**涟漪只覆盖 bg + 立绘**，氛围色和粒子层不参与扭曲。
波带掠过时，atmo 染色和粒子是"穿过"涟漪而非"被"涟漪扭曲。
这正是它"淡"和"轻"的根源 —— 如果以后想做"全图整体折射"，
必须接受**手感变重 + 性能变贵**两个副作用，参考 `wave.js`
重写期间的失败尝试。
