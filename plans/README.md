## 三层架构

```
plans/
├── 00-愿景/              产品哲学,跨版本不变
├── 01-通用设计规范/      引擎无关的设计规则(交互 + 视觉)
└── 02-测试版/           当前实验版的落地实施
```

| 层 | 用途 | 跨版本变化 | 主要读者 |
|---|---|---|---|
| **00-愿景** | 顶层产品哲学,Echo 是什么 | 不变 | 所有人 |
| **01-通用设计规范** | 引擎无关的交互 / 视觉设计规则 | 缓慢演进 | 开发、设计、新成员入门 |
| **02-测试版** | 当前实验版的剧本 / 素材 / 实现细节 | 跟版本绑死 | 实现过程参考、迭代记录 |

## 写新文档归哪层?

| 内容 | 归层 |
|---|---|
| 跨任何 Echo 形态都成立的产品理念 | 00-愿景 |
| 跨任何引擎、跨任何具体剧本的设计规则 | 01-通用设计规范 |
| 跟具体素材 / 剧本 / DOM / 数值绑死的 | 02-测试版 |

**判断不清楚时**:

1. 先放 02-测试版
2. 在 [待讨论清单.md](01-通用设计规范/待讨论清单.md) 加一条候选
3. 出现第二次使用 / 第二个落地版本时,再提升到 01-通用设计规范

- **加新互动玩法** → 交互设计 §二 → 02-测试版/互动玩法-摸摸 作为模板
- **找设计原则的源头** → 01-通用设计规范 任一文档 + 待讨论清单
