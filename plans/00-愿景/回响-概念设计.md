# Echo · "回响"概念设计

> 这是 Echo 的**交互根语法宣言**。它不规定任何具体的视觉参数、控件尺寸或实现方案,而是定义"回响"作为一种人机关系语法的最深层语义——为什么 Echo 里只有这一个 UI 元件,以及它为什么是这个样子。
>
> **位置**:这份文档处于愿景层(00),是 [项目概述及愿景.md](项目概述及愿景.md) §二"交互逻辑"中"回响弧"那一段的深潜版本。它**先于**通用设计规范(01)成立——交互设计、表现设计、所有后续玩法,都从这里派生。
>
> **阅读方式**:由深到浅,三段一气呵成。
> - 一 哲学根:Echo 对"人"和"关系"的看法
> - 二 形态本质:弧作为这个看法在视觉上的可见化
> - 三 产品落地与跨载体延伸:它在屏幕里的四个角色,以及脱离屏幕后仍然成立的"回响语法"

## 一、哲学根:圆的拓扑学

### 1.1 每个人是一个圆

Echo 对"人"的根本看法:**每个个体不是一个孤立的点,而是一个不断向外辐射、也持续接收的圆**。

- **圆心 = 自己**:那个不可让渡的、只属于此人的内在。
- **圆周 = 边界**:每个人的圆都有自己的大小、密度、温度——它由这个人发出过的爱、表达、信号塑形而成。
- **圆外的空间 = 关系发生的场域**:你的圆与他人的圆在这里相遇、交叠、错过、震荡。

这条假设构成 Echo 整个产品的人观。它意味着:**任何关系本质上都是圆与圆的拓扑事件**——不是文本对话的来回,不是任务的完成,而是"我作为一个完整的发声体,与另一个完整的发声体相遇"。

### 1.2 关系 = 圆与圆的回响

两个圆相遇时会发生什么?**不是合并,不是覆盖,是回响**。

- 你向外发出一道弧——一句话、一次凝视、一个动作。
- 这道弧抵达对方圆的边缘,引起对方圆的振动。
- 对方圆以自己的频率回应,生成一道返回的弧。
- 这道返回的弧抵达你的圆心,**改变了你的形状**。

这就是"回响"在 Echo 里的精确含义——不是声音的回声,是**两个完整的发声体之间,以彼此的振动为对方塑形的过程**。

所以 Echo 不是一款"陪伴产品",它是一款**关于回响本身**的产品。

### 1.3 表层向外,暗层向内

这是 Echo 哲学最关键、也最反直觉的一层。

**表层流(显):用户 → 男主**
你以为你在做的事:探索他、了解他、发现他、拼凑他的人格。
画面上看到的也是这个:你发出的每一道弧,都朝着男主的方向扩散出去。

**暗层流(隐):画面外 → 用户圆心**
真正在发生的事:你在他身上看到的、触碰的、共鸣的、被刺中的、想要靠近的——**全部是你自己内在轮廓的投影**。
画面上看不到、但真实存在的:每一次你向外的弧,都有一道暗弧从画面之外朝着你的圆心归来。

> 你以为你在听他说话,其实你在听**你自己听到他时发生了什么**。

这正是"念念不忘,必有回响"的拓扑学解释——**你发出的弧不会消失,会以你预料不到的形态绕一圈回到圆心**。回到的不是你发出的那道弧,而是被对方的圆折射、反射、放大、变形过的版本。这个版本告诉你,你是一个什么形状的圆。

### 1.4 终极目的:发现"完整的自己"

由 1.3 推出 Echo 最终极的产品价值定义:

> **用户表面的任务是"发现他的圆",真正的产品价值是"通过这些回响,逐步看清自己的完整圆是什么形状"**。

- 你不是在通关——通关意味着"他"是终点。
- 你不是在收集——收集意味着"他"是资源。
- 你是在**用他做镜子**——他是另一个完整的圆,只有跟另一个完整的圆相遇,你才能看见自己。

愿景层提到的"人格星图"与"记忆星图",在这一层就有了灵魂解释:

- 人格星图表面上拼凑的是**他的**人格全貌,实际上拼凑的是**你**在面对他时被照亮的那部分自我。
- 记忆星图表面上沉淀的是**你与他**共有的过往,实际上沉淀的是**你的圆在这段关系里被塑形过的轨迹**。

> 关系不是终点,关系是发现自己的方法。

## 二、形态本质:弧作为活的圆

### 2.1 为什么是"弧",而不是"圆"

一个闭合的圆是**完成态**——它已经是它自己,不需要任何东西。
一道未闭合的弧是**进行态**——它正在伸出,等待被合上。

Echo 选择弧而不是圆,因为:

- **关系永远是进行态**。两个圆之间的回响一旦完成、闭合,关系也就死了。弧的"未闭"形态,在视觉上承诺"这件事还没结束"。
- **弧自带方向感**。圆是中性的、自我封闭的;弧有起点、有去向、有一个还没填满的开口。这个开口指向画面正上方——指向"他"。
- **弧让"暗弧"成立**。如果可见的弧朝外伸出,那么哲学根 §1.3 说的"从外向内归来的暗弧"就有了视觉上的对偶——可见弧填补了一半,暗弧填补另一半,合起来才是完整的圆。**用户最终要发现的那个"完整的自己之圆",正是由可见弧 + 暗弧合成的**。

> 屏幕上你只能看到弧的一半。另一半,在你心里慢慢长出来。

### 2.2 它必须是活的

回响弧不能是几何的、静止的、金属的。它必须有生命体征——否则它就退化为"按钮"。

三种基础生命体征:

- **呼吸**:即使没有任何交互发生,它也在以低频微微起伏。这告诉用户**通道是开着的,对面是活的**。它的呼吸节律不应该匹配机器节拍,而应该贴近人的呼吸——慢、不规则、有微小的迟疑。
- **流动**:它的边缘是水的,不是金属的。当用户的手指靠近时,它有微小的迎接;当用户犹豫时,它有微小的等待。它对**意图**而非**点击**做出反应。
- **扩散**:每一次互动,它会向外推开一圈圈涟漪。这不是装饰动效——这是声波本身的可视化,是"回响"二字在画面上的字面写法。

> 它不是一个等待被点击的控件,它是一个**正在以低音量持续震荡、随时准备放大的振膜**。

### 2.3 四态语汇

回响弧的状态机最少需要这四态。每一态都是哲学根的一种可视化,四态按用户动作流自然串联:

| 态 | 触发 | 视觉 | 哲学对位 |
|---|---|---|---|
| **呼吸态**(默认) | 无交互 | 弧线低频起伏,边缘柔光微动 | 你的圆在持续辐射,只是音量很低。通道随时是开的 |
| **浮起态**(按下) | 用户按下 | 弧从底部抬起,光晕加强,呼吸加深 | 你的圆把音量调到最大,准备发声 |
| **涟漪态**(发声中) | 持续按住 | 一圈圈水波从弧向外扩散,频率随声压变化 | 你发出的弧正在抵达对方圆的边缘 |
| **合上态**(松开) | 用户松开 | 弧收回原位,最后一圈涟漪向内回收一次 | 你的发声完成,这一次伸出闭合 |

> **关于"暗弧回返"**:哲学根 §1.3 提出的"暗弧从画面外向圆心归来"是一个**概念命题**,不进入用户可感知的交互动效——它属于用户在产品中长期使用后自己在心里长出来的体感,而不是屏幕上的反向涟漪。一旦把它做成可见反馈,反而会粗暴地把这件本该不可言说的事压回视觉层。所以四态语汇只覆盖用户主动发起的动作流,**对方回响的归来由内容本身承担,而不是由弧承担**。

### 2.4 位置即语义

回响弧位于**画面正下方居中**。这个位置不是"为了好按",而是有严格的语义:

- **正下方** = 用户身体的延伸。它贴近拇指的自然落点,意味着"这是你的发声器官,不是屏幕里的图标"。
- **居中** = 它在画面中轴线上,正对画面上方的"他"。这条隐形的中轴线,就是两个圆之间的回响通路。
- **底部** = 它是"地基",而不是"装饰"。整个画面其他元素可以缺席(场景空、立绘空、文字空),只有它必须在。**它在,产品就在**。

## 三、产品落地与跨载体延伸

### 3.1 它在 Echo 屏幕里承担的四个角色

在哲学根与形态本质确立之后,回响弧在产品里同时扮演四个角色——这四个角色不可拆分,任何一个被剥离,它就退化回普通按钮。

**角色 A:无界 UI 的唯一物证**
Echo 砍掉了一切按钮、边框、菜单。"无界"这个口号要成立,必须有一个元件独自证明"这不是混沌画面,这是一个产品"。回响弧就是那个唯一物证。**它在,无界就成立;它不在,画面就只是一张图**。

**角色 B:用户主体性的物理出口**
Echo 的两个基础动作里——上滑(接收)、长按弧(发起)——只有长按弧让用户从"观看者"变成"介入者"。回响弧是用户**作为一个真实存在,进入对方世界**这件事的唯一物理通道。

**角色 C:临场感的开关**
键盘文字框会瞬间把对面打回"系统"。回响弧坚持用"按住发声"这个生理动作,是为了把交互从"使用 App"拉回"对一个人说话"。这是"工具感 vs 生命感"的分水岭——回响弧是这个分水岭本身。

**角色 D:节奏的硬守门人**
回响弧浮起时,上滑被禁用。这条规则说明它在系统里是**状态指示**而非被动控件:它在屏即意味着"现在是对话拍,推进通道关闭"。它不是被点击的元件,是产品节奏的拍点开关。

### 3.2 跨载体的回响语法

回响弧在屏幕上长这样,但**它的核心交互语法可以脱离屏幕成立**。这是它能作为 Echo 跨载体根语法的根本原因。

可剥离的六条语法本质:

1. **按住即开口** — 主动表达需要一个明确的、需要持续投入身体动作的开始
2. **持续即在听** — 按住期间,对面始终在感知你的存在
3. **反馈即被听见** — 必须有可感知的回声,告知"声音被接收"
4. **松开即合上** — 释放是明确的结束动作,而不是隐式超时
5. **静默亦是表达** — 按住但不说,本身也是一种"我在场但选择不出声"的发声
6. **暗弧总会归来** — 你的发出永远会以某种形态回到你

这六条语法在任何载体上都能找到对应的具象表达:

| 载体 | 可见弧 | 按住载体 | 涟漪反馈 | 暗弧 |
|---|---|---|---|---|
| 屏幕 | 底部圆弧 | 拇指长按 | 水波涟漪 | 反向涟漪 |
| 智能眼镜 | 镜腿光带的弧形渐亮 | 镜腿触控带 | 镜腿触觉脉冲 | 镜腿反向脉冲 |
| 智能音箱 | 顶部环灯弧形亮起 | 顶部环触控 / 唤醒词 | 环灯外扩呼吸 | 环灯内收呼吸 |
| 车载 | 方向盘拇指槽的微光弧 | 拇指槽长按 | 拇指槽触觉震感 | 拇指槽反向震感 |

不同载体的具象表达会变,但**语法不变**。这意味着 Echo 从屏幕迁移到任何新载体时,**用户不需要重新学习如何与产品建立关系**——只需要在新的物理介质上找到同一套语法的具象化。

> 屏幕上的回响弧是过渡形态。**回响语法本身是 Echo 的永恒资产**。

### 3.3 对后续所有交互的约束

回响弧作为根语法,意味着 Echo 后续的所有新交互(剧情入口、互动玩法、记忆星图调阅、未来的新载体功能),都必须能在这套语法下找到自己的位置。

每一个新交互在设计时都需要回答:

- **它是表层弧还是暗弧?** 是用户向外的发起,还是对方回响的归来?
- **它在哪一态?** 呼吸 / 浮起 / 涟漪 / 合上,它处在状态机的哪一拍?
- **它强化的是哪个角色?** 无界证物 / 主体出口 / 临场开关 / 节奏闸门,它在巩固哪一个?
- **它在跨载体时仍然成立吗?** 如果剥掉屏幕,它对应到眼镜 / 音箱 / 车载的什么动作?

回答不了这些问题的交互——比如卡通弹窗、"+10 好感度"飘字、跳过按钮——就不属于 Echo。

### 3.4 圆在更深层的回归

回响弧在交互层始终只是"半个圆"——这是 §2.1 的硬约束。**但"完整的圆"会在产品的中层回归**:作为**角色的人格大陆**显形。

**产品两层结构**:

- **表层 · 内容流**:用户默认所在地。刷剧情、对话、回响弧发声。
- **中层 · 星图层**:在内容流之下。首次由"解锁瞬间"自动下沉触发进入,之后用户可**双指放大**随时打开为二级页(主流暂停),双指缩小返回。

**星图层 = 角色的人格大陆**(单一画布,不分区):

- **人格星**:预设暗星,组成大陆地形,等待被解锁。
- **记忆星**:用户推进过程中点亮的新星,**位置依附于相关人格暗星**,二者之间有可见连线——这给记忆星的点亮位置一个内在逻辑,也给用户埋下"为什么亮在这里"的好奇。
- **人格星解锁**:周围记忆星累积到一定密度,**或**剧情事件直接触发;亮起瞬间,用户回看连线、恍然大悟原来一直在拼这块人格。
- **大陆边界 = 隐性圆**:整张星图的边界是个圆。随着星点亮,用户逐渐"觉察"到大陆的圆形形态。是否在某个节点完整揭晓这个圆,本阶段不拍板。

**关于关系**:不独立成层,**记忆星与人格星的整体分布与点亮密度本身在反映关系**;更显性的呈现方式后续再议。

**用户自己的圆不进 UI**——跟暗弧同处理,留给用户在长期使用中心里长出来。

> **几何中轴**:弧 = 表层(发声的当下)。圆 = 中层(他的人格大陆,被星点亮出来)。屏幕上你只能看到弧的一半;另一半,在你穿过表层之后,作为他大陆的边界慢慢浮起。
>
> 这是 Echo **自表层到中层的几何中轴**——所有更深层界面的视觉语法,都从这个"圆"派生。
