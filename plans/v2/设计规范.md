# v2 设计规范

> v2 的设计宪法。涵盖**交互语义**与**视觉层级**两件事，凡是与"用户能感知到什么、画面怎么分层"相关的硬约束都写在这里。
>
> 配套：[分场层级.md](分场层级.md)（每场怎么用这套系统）、[素材清单.md](素材清单.md)（资产现状）、[节奏起伏.html](节奏起伏.html)（覆盖率曲线）。
>
> 实现锚点：[v2/index.html](../../v2/index.html)、[v2/js/screen.js](../../v2/js/screen.js)、[v2/js/atmo.js](../../v2/js/atmo.js)、[v2/js/player.js](../../v2/js/player.js)。

## 一、交互语义

v2 全程只 4 种交互。统一 + 简单是首要目标，向短视频"刷"语义对齐。

| 交互 | 含义 | 触发条件 | 反馈 |
|---|---|---|---|
| **上滑（轻）** | 同屏推进下一段 | 当前段已展开完成 | 当前段淡出 → 新段淡入（背景不动，立绘可微动） |
| **上滑（重）** | 切到下一个场景 | 屏内所有段落播完 | 整屏向上推走 + 新场景从下浮入（带水波涟漪） |
| **圆弧长按** | 你说话 | 屏内对话节点 | 圆弧浮起 + 语音/文字输入 |
| **摸摸**（持续移动） | 抚摸他 | 第 7 场景的亲密点 | 立绘局部反应、轨迹光痕、敏感区命中 |
| **点按**（辅助） | 催当前文字立即展开 | 文字打字机展开过程中 | 当前段一次性显示完整（**不**推进） |

**关键原则**：

- 上滑是唯一推进操作。"轻"和"重"由系统自动判断（当前位置是不是屏内最后一段），用户只做一个动作
- 一段文字 = 40-80 字、2-3 句，承载一个完整动作或心理转折
- 圆弧期间上滑无效——必须长按说话或选"不出声"完成
- 点按只用来催文字，不参与推进——避免"点按 vs 上滑"两套语义混乱
- 摸摸期间手指松开 = 进度回退 30%，2s 内回来继续算；超过 2s 彻底失败

## 二、视觉九层堆栈

```
┌──────────────────────────────────────────┐
│ ⑨ 文字层（旁白/对白/inner/aside）       │ paragraph.js
├──────────────────────────────────────────┤
│ ⑧ 交互 UI 层（圆弧/手势 tip）           │ ring.js / swipeTip.js
├──────────────────────────────────────────┤
│ ⑦ 特效·伴随（屏震/闪/推拉，瞬时）       │ ★ 单元素原则之外
├──────────────────────────────────────────┤
│ ⑥ 特效·主导（粒子/光柱/训狗字符浮起）   │ ★ 单元素原则
├──────────────────────────────────────────┤
│ ⑤ 氛围层 · emotion（角色之上）          │ ★ 染整张画面
├──────────────────────────────────────────┤
│ ④ 角色层                                  │ character.js
├──────────────────────────────────────────┤
│ ③ 氛围层 · env（角色之下）              │ ★ 只染场景
├──────────────────────────────────────────┤
│ ② 场景层（单体 PNG / 整图 + 遮罩）      │ ★ 单元素原则
├──────────────────────────────────────────┤
│ ① 极暗底（bgColor 纯黑/深色）           │ —
└──────────────────────────────────────────┘
```

**单元素原则（最关键）**：

- 场景层：任意时刻只 1 个元素。来源可以是 PNG 切图，也可以是整图局部露出
- 氛围层：env 与 emotion 各自只 0 或 1 个 preset，**两者可同时存在**（一个染场景，一个染整张画面）
- 特效·主导：任意时刻只 1 种主导特效

## 三、场景层

**核心定义**：场景层 = 任意时刻画面中那 1 个明确的可识别元素。覆盖率沿用设计：20-30% / 50-60% / 100%。

### 3.1 两条素材路线（并列等价）

| 路线 | 含义 |
|---|---|
| **PNG 切图** | 一张干净的透明 PNG（鱼尾、藤蔓、食人花……），整张图就是一个单体 |
| **整图局部露出** | 整张场景图（骸骨、宅院、羊人吃尸体……）通过遮罩控制露出区域，**这块区域 = 一个单体** |

> 一张整图可以承载多个单体（露出不同区域 = 不同单体）。整图与切图**不在同一画面共存**。

### 3.2 整图遮罩形状

整图永远以 cover 100% 铺，露出靠遮罩控制：遮罩内是图，遮罩外是极暗底。

- **椭圆遮罩**（默认）：中心 `(cx, cy)`、半径 `(rx, ry)`、柔边
- **线性遮罩**：上半区 / 下半区 / 左半区 / 右半区

### 3.3 单元素切换

- **同源切换**（同一张整图露出不同区域）：旧露出区域**渐变扩大、缩小或位移**到新区域
- **异源切换**（换成另一张图的单体）：旧元素淡出 → 极暗底瞬间 → 新元素淡入

### 3.4 留白即设计

被压暗 / 不在露出区域 / 没有切图覆盖的部分，全部交给极暗底。**留白本身是设计**——给玩家想象空间。

## 四、氛围层

### 4.1 双挂载位

| 模式 | 表达 | 挂载位 | 染色范围 |
|---|---|---|---|
| **env** | 环境氛围：明暗、时间、天气、地点性 | 角色之下 | 只染场景层 |
| **emotion** | 心理氛围：冷漠、亲密、惊吓、愤怒 | 角色之上 | 染整张画面（场景 + 角色 + 一切） |

**为什么分两个挂载位**：env 在底保护角色色调一致性；emotion 在顶让心理冲击成为整体感受。"美好晨光下心境忽然变冷" = env(`dawn-warm`) + emotion(`cold-shock`) 一闪。

### 4.2 氛围预设清单

| Preset | 建议模式 | tint | blend | vignette | 用途 |
|---|---|---|---|---|---|
| `dark-water` | env | 深蓝 rgba(20,35,70,0.85) | multiply | 0.55 | 场 1 黑暗水中 |
| `cold-blue` | env | 冷蓝 rgba(70,110,180,0.75) | overlay | 0.4 | 场 4 火林 / 场 6 月夜洞穴 |
| `flame-warm` | env | 暖橙 rgba(255,140,60,0.5) | overlay | 0.15 | 场 4 烈焰救场 |
| `scorched` | env | 灰红 rgba(180,95,60,0.7) | overlay | 0.4 | 场 5 焦土 |
| `dawn-warm` | env | 暖橙黄 rgba(255,195,135,0.55) | overlay | 0 | 场 7 晨光 / 场 8 入场 |
| `fog-mansion` | env | 灰白偏冷 rgba(170,165,180,0.7) | multiply | 0.45 | 场 8 钩子宅院 |
| `flush-rose` | emotion | 暖粉 rgba(255,150,150,0.35) | screen | 0 | 摸摸 50-100% 脸红 |
| `cold-shock` | emotion | 金红 rgba(255,70,70,0.5) | multiply | 0.3 | 钩子瞳缩瞬间 |
| `red-alert` | emotion | 全屏红 rgba(180,30,30,0.55) | multiply | 0.5 | 危险/愤怒瞬间 |

> 预设清单不是封闭的。剧本推进时可以新增，加在 [v2/js/atmo.js](../../v2/js/atmo.js) `PRESETS`。

### 4.3 切换规则

- 切场景 beat → env 渐变到新场景的默认预设；emotion 重置为空
- 段落推进 → 默认不变，剧情明确需要时切（摸摸 4 阶就是 4 次氛围切换）
- emotion 入场时 env 不退——env 维持环境基调，emotion 在顶加情绪冲击

### 4.4 立绘差异度低时的协作

当立绘资产差异度不够（如摸摸 4 阶几乎同姿态）时，**emotion 氛围切换是补强主力**：

```
摸摸:    0% → 25% → 50% → 75% → 100%
env:     dawn-warm（不动）
emotion: 无 → 无 → flush-rose浅 → flush-rose → 无（让 dawn-warm 接管）
立绘:    原图  原图  脸红切图     脸红切图   闭眼笑切图
```

立绘单看几乎不变，配合 emotion 递进 + 特效，体验上有清晰梯度。

## 五、特效层

### 5.1 哲学：克制 + 抽象

> 前端直接画的写实细节几乎一定廉价。能用粒子、光、震动表达的，就不画 SVG 物件。

**允许 ✅**：抽象粒子（鬼火、尘、雾、雨、火星、训狗字符浮起）/ 全屏动态（屏震、白闪、镜头推拉）/ 短促色彩失真

**禁止 ❌**：在角色身体上画 SVG（手腕画绳子、嘴角描红线）/ 写实物件 SVG（杯子、果子）/ 卡通化 UI 弹窗与"+10%"飘字

### 5.2 主导 vs 伴随

| 类别 | 含义 | 占槽位 | 任意时刻最多 | 例子 |
|---|---|---|---|---|
| **主导** | 长生命的视觉信号，构成画面"特效元素" | ✅ | 1 种 | 鬼火、尘飘、月光柱、晨光柱、训狗字符浮起 |
| **伴随** | 瞬时动态行为，不构成视觉"元素" | ❌ | 任意叠加 | 屏震、白闪、镜头推拉、烈焰爆开 |
| **切换** | 状态切换（开/关） | ❌ | 任意叠加 | 雾、灯笼、纸扎人 |

> 判断标准：**这个特效如果消失了，玩家会觉得"画面少了什么东西"** → 主导；**消失只是"动作没发生"** → 伴随。

### 5.3 训狗字符浮起：特例

训狗诗字符浮起归特效层（不归文字层），用墨迹由淡到浓 / 字符逐个浮起的视觉风格区分"画里的字"与"旁白文本"。**这是特效层唯一允许的"画文字"**。

## 六、覆盖率口径（节奏起伏图的 Y 轴）

| 状态 | 计入 | 互斥关系 |
|---|---|---|
| 纯极暗 bg | 0% | — |
| **单体 PNG 集**（1-N 个） | 累加 20→70% | 互斥组 A |
| **整图 reveal mask** | mask 面积百分比（25→70%） | 互斥组 A |
| **整图全揭** | 100% | 互斥组 A |

**互斥组 A**（单体集 / 整图 mask / 整图全揭）三选一，同时只能存在一种。**单体之间可叠加**。

### 6.1 设计目标

- 50% 时间停留在 **20-30%**（单体探索期）
- 中段叠加扩到 **50-60%**（多单体 / 局部扩大）
- 高潮整图全揭 **100%**

详见 [节奏起伏.html](节奏起伏.html)。

## 八、状态机：每个 beat 的视觉声明

每个剧情 beat 可以**只声明改变量**，未声明的层保持当前状态：

```js
{ t: 'scene',       el: '鱼尾.webp' }            // 设置场景层单体
{ t: 'scene',       reveal: { shape: 'ellipse', cx, cy, rx, ry } }  // 调整遮罩
{ t: 'scene',       clear: true }                // 清空场景层
{ t: 'env',         preset: 'dark-water' }       // 切换 env
{ t: 'env',         clear: true }                // 清空 env
{ t: 'emotion',     preset: 'cold-shock' }       // 切换 emotion
{ t: 'emotion',     clear: true }                // 清空 emotion
{ t: 'fx-dominant', kind: 'ghost-fire' }         // 切换主导特效
{ t: 'fx-dominant', clear: true }                // 清空主导特效
{ t: 'burst',       kind: 'shake', duration: 200 }  // 触发伴随行为
```

**默认行为**：
- 切场景 beat = 触发场景层与 env 切换；emotion 与主导特效重置为空
- 段间 beat = 未声明的层不变
