# AI 实时生成感 · 交互节奏方案

> 配套：[demo-script.md](demo-script.md)（v2 剧本）、[demo-flow.md](demo-flow.md)（节奏方案）
> 目标：让 AI 的耗时变成"用户参与的仪式感"，而不是"系统的等待"。每一段过渡动画的设计原则 —— 让用户看到能量在流动、内容在生成、场景在被"织出来"。
> 状态：待逐项确认后实施。

---

## 设计原则

整个 demo 的核心理念：**用户 AI 语音输入，剧情实时 AI 产出，场景图 / 素材 AI 生成**。

但 AI 生成本身是有延迟的。如果每次"等"都是空白等待，用户会觉得"系统反应慢"；如果每次等都填上**主题化的视觉运动**（光在流动、文字在生成、图在浮现），用户会觉得"我的输入正在被处理、世界正在被织出来"——延迟变成仪式感。

参考心智模型：Midjourney 的渐变进度、ChatGPT 的流式 token、Suno 的波形成歌。

## 更新 1 · 语音传送暖光（每次对话都用）

### 触发时机
每次长按弧 → 松手发送（demo 全程共 8 次），在 user bubble 打完字后、角色 reply 浮起前。

### 视觉拆解（总长 ~2.8s）

| 段 | 时长 | 看到什么 |
|---|---|---|
| A 凝聚 | 400ms | user bubble 的字"碎成"暖白光点，bubble 本体淡出消失 |
| B 上送 | 1800ms | 屏底升起一道暖白纵向光带，匀速向上扫过整屏；前沿带几粒微光粒子向上飘 |
| C 抵达 | 600ms | 光带触到角色头部位置时化掉，角色头部出现暖光晕 + 一个微动作（耳朵颤一下 / 眼瞳一闪），然后才浮起角色 bubble |

### 实现方案
- 新增 `transmitToCharacter()` 函数，建议放 [v2/js/fx.js](../../v2/js/fx.js)
- 在 [v2/js/ring.js:148](../../v2/js/ring.js#L148) 的 `await showDialogue('你', text)` 之后、`recordPressSuccess()` 之前调用
- C 段的角色微反应可以复用现有 `characterGlow()` ([v2/js/fx.js:300](../../v2/js/fx.js#L300))，加一个 pose tic 微动画
- A 段需要替代现有 `driftAway()`（[paragraph.js:82](../../v2/js/paragraph.js#L82)）对 user bubble 的处理，让字"碎成光点"而不是漂走

### 对总时长的影响
8 次 × 2.8s ≈ 多出 22 秒。demo 从 10:00 拉长到约 10:25，可接受。

## 更新 2 · 旁白文字 = 流式 token + 光标

### 触发时机
所有旁白 / 内心 OS / aside 段（demo 全程共 18+ 段）。

**对话气泡保持原样**（一字一字 = 说话节奏），让"说话"和"AI 生成"在视觉上自然区隔。

### 视觉拆解
- **流式节奏**：不再 1 个字 1 拍，改成 2-3 个字一组蹦出来；每组之间的间隔随机抖动 ±30%，模拟 LLM 流式输出的节奏感
- **末尾光标**：最新字符后跟一个发光小竖条（`▎` 形态），整段打完时这个光标放大淡出，像火星散去
- **不做**逐字墨水晕开 —— 文字样式后续单独处理

### 实现方案
- [v2/js/paragraph.js:31-68](../../v2/js/paragraph.js#L31-L68) 的 `startTyper()` 增加 `mode` 参数：
  - `'char'`：对话用，保持现状（一字一拍）
  - `'token'`：旁白用，新逻辑（2-3 字一组 + 抖动）
- 旁白系列函数 `showNarration` / `showInner` / `showAside`（[paragraph.js:124-126](../../v2/js/paragraph.js#L124-L126)）传 `mode: 'token'`，对话保持默认 `'char'`
- 光标元素：在 typer 节点末尾追加一个 `<span class="gen-cursor">`，整段完成时单独触发它的散去动画再移除

### 注意点
- 流式 token 的字符分组要避免把标点和上一个字断开（"。"、"，"、"——" 应该跟上一组）
- 抖动范围控制在 ±30%，太大会显得"卡顿"而不是"流式"

## 更新 3 · 切场景 = 新场景图由下到上溶解

### 触发时机
上滑·切场（demo 全程共 7 次），**且当下一场景的背景图与当前不同**时才生效。

> 例外说明：场景 1/2/3 共用 `cj1.jpg`，这两次切场没有图片变化，**不触发**溶解效果，保持现有的整屏上推。否则会出现"图片溶解但其实没换图"的怪异感。

### 视觉拆解
- 旧场景按现有方式向上推走（保持现有切场动画）
- 新场景图入场时不是直接铺满：
  - 图片初始整体不可见
  - 一层"由下到上"的羽化遮罩从屏底慢慢揭开图片
  - 大约 1.6-2s 完成
- 遮罩的边缘是**柔和过渡的**（不是一条亮线，而是一段半透明的渐变带），给人"从下方溶解出来"的感觉，跟用户上滑的方向自然延续
- **不加**任何高亮线、粒子或闪光（这一点是用户明确否决了"扫线渲染"方案的核心要求）

### 实现方案
- [v2/js/screen.js](../../v2/js/screen.js) 的 `transitionToScreen()` 函数中，在新屏背景图上加一个 CSS mask
- mask 位置从"完全遮挡"动画到"露出屏顶"，timing 用 ease-out
- 加判断：`newBg !== currentBg` 才启用溶解，否则走现有过渡
- 不影响现有的 `mountFirstScreen()`（首屏不需要这个效果）

## 当前未决项

### A. 长按弧形微抖（"听见你的声音"）
**未做决定。** 长按录音期间，弧线本身做轻微的纵向波动，看起来像在采集声波。让长按这件事自己有信息感。约 30 行代码，加在弧的 SVG 上（[v2/js/ring.js](../../v2/js/ring.js) state-recording 状态期间）。

### B. 整体节奏数值放慢
**倾向先不动。** 更新 1 已经在每次对话塞了 2.8s 仪式动画 = 实质放缓。是否还要再额外把"段落停留"和"漂走"的时间也加长？比如 `HOLD_NARRATION` 1500ms → 2200ms（[paragraph.js:22](../../v2/js/paragraph.js#L22)）。

建议先把更新 1+2+3 上完看体感，再决定要不要补这一刀。

## 实施顺序建议

按"改动最小 → 改动最深"顺序，每完成一项可单独预览验证：

1. **更新 2（旁白文字效果）** —— 改动最小、立刻能看到 AI 生成感，风险低
2. **更新 1（暖光传送）** —— demo 的核心仪式感，影响每次对话
3. **更新 3（场景溶解）** —— 改动最深，要动 screen.js 和切场逻辑

每完成一项，user 体感后再决定是否调整 / 进入下一项。

## 已否决方案（备忘）

避免重复讨论：

- **扫线渲染（切场图）**：不做。一道亮白线扫过新图边变锐——用户认为太抢戏。改为"由下到上溶解"。
- **逐字墨水晕开（旁白）**：暂不做。文字样式后续用户自己处理。
- **织线间奏（切场）**：不做。功能与"由下到上溶解"重叠，二选一。
- **关键时刻才用暖光传送**：不做。用户明确每次对话都要用，不分主次。
- **旁白每段都加 ink-bloom**：不做。同上，分主次的方案被否决，但通过"只用流式+光标"达成了不抢戏的目的。
