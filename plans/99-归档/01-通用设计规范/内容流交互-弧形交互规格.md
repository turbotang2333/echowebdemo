# 弧形交互规格 · Unity 实现参考

> 内容流中两个弧形交互元素的完整实现规格。
> 配套原型：`prototypes/arc-circle-test.html`（浏览器打开可体验全部交互）。

---

## 一、坐标体系与适配

### 1.1 两个基准单位

```csharp
float sw = Screen.width  * 0.01f;  // 屏幕宽度的 1%
float sh = Screen.height * 0.01f;  // 屏幕高度的 1%
```

### 1.2 每个参数的缩放基准

竖屏手机宽度稳定、高度随机型变化。规则：**弧"长什么样"跟宽走，弧"在哪里"跟高走。**

| 跟宽走 (sw) — 弧的外观 | 跟高走 (sh) — 弧的位置与运动 |
|---|---|
| 圆半径 | 露出量（距屏幕底边多远） |
| 描边粗细 | 呼吸浮动的上下限位置 |
| 光晕扩散范围 | 呼吸幅度（上下位移量） |
| 涟漪线宽 | 录音上升量 |
| 预告光半径 | 收回目标位置 |
| 弧顶亮边线宽 | 引导蒙层覆盖范围 |
| | 引导文字位置 |
| | 手势响应区域（下 1/3） |

**效果**：长屏手机上弧和短屏手机看起来一模一样，只是上方内容区域更大。

### 1.3 坐标原点

本文档以**屏幕左下角为原点，Y 轴向上**（Unity Screen 坐标系）。"屏幕底边"= Y=0，"屏幕顶边"= Y=Screen.height。

### 1.4 手势阈值的缩放

上滑距离阈值和速度阈值用**物理像素**，不做屏幕比例缩放——手指的物理移动距离在不同手机上是一样的。

## 二、共享圆

两个元素共享同一个圆，只是渲染方式不同（描边 vs 填充）。

```csharp
float R  = 120 * sw;            // 半径 = 屏幕宽度 × 1.2
float cx = Screen.width * 0.5f; // 圆心 X = 水平居中
float cy = peekY - R;           // 圆心 Y = 弧顶位置往下偏移一个半径
// peekY = 当前状态的露出量，即弧顶距屏幕底边的高度（见下文各状态定义）
// 验证：圆的最高点 = cy + R = peekY ✓
```

弧的可见部分：圆顶部高于 Y=0（屏幕底边）的区域。两端自然没入屏幕底边以下，不需要裁剪。

## 三、回响弧（描边 · 输入用）

纯描边线，无填充。用户长按屏幕下 1/3 区域触发。

### 3.1 状态参数表

| 状态 | 露出量 | 描边粗细 | 描边 alpha | 光晕 alpha | 持续时间 |
|---|---|---|---|---|---|
| **入场** | 11sh → 16sh | 0.28sw | 0 → 0.7 | 0 → 0.15 | 1.0s |
| **呼吸** | 16sh ± 1.375sh | 0.28sw | 0.5 ~ 0.9 | 0.05 ~ 0.25 | 循环 4.2s |
| **录音** | 16sh → 22sh | 0.39sw | 0.95 | 0.15 → 1.0 | 按住持续 |
| **收回** | 22sh → 5.5sh | 0.28sw | 0.8 → 0 | 脉冲 0→0.6→0 | 0.45s |

> 描边粗细说明：原型中 3px 对应 1080 宽屏幕 = 3/1080 ≈ 0.28sw。录音态 4.2px ≈ 0.39sw。
> Unity 实现应使用 sw 单位（随屏幕宽度缩放）。网页原型因测试设备固定，使用了绝对 px 未做缩放，不影响视觉基准——以 sw 值为准。

### 3.2 入场 arc-enter

```
时长: 1.0s
缓动: t' = 1 - pow(1-t, 2.5)   // t=0→1, t'=ease-out

露出量 = lerp(11*sh, 16*sh, t')
描边alpha = 0.7 * t'
光晕alpha = 0.15 * t'
```

**长按打断**：入场期间用户按下屏幕下 1/3，记录当前 t 值，剩余行程在 0.15s 内走完（线性加速），然后进入录音态。

### 3.3 呼吸 arc-invite

```
周期: 4.2s
计时: 从进入此状态开始的 elapsed（不用全局时间，保证与入场结束值衔接）

b = sin(elapsed / 4.2 * 2π)       // b: -1 ~ +1，起始 b=0
露出量   = 16*sh + 1.375*sh * b
描边alpha = 0.7 + 0.2 * b         // 0.5 ~ 0.9
光晕alpha = 0.15 + 0.1 * b        // 0.05 ~ 0.25
```

**为什么用相对时间**：如果用全局时间，进入呼吸态的瞬间 sin 相位随机，会导致位置和 alpha 跳变。用相对时间保证 sin 从 0 开始，与入场结束值（露出量=16sh, alpha=0.7, 光晕=0.15）精确对齐。

### 3.4 录音 arc-record

```
上升动画: 0.4s, t' = 1 - pow(1-t, 3)

露出量    = lerp(16*sh, 22*sh, t')      // 上升 6sh
描边粗细  = lerp(0.28*sw, 0.39*sw, t')
描边alpha = 0.95（固定）
光晕alpha = lerp(0.15, 1.0, t')
```

**涟漪**（录音期间持续生成）：

每道涟漪是一个**独立的圆弧实例**，有自己的圆心 Y 和半径，每帧都在变。建议用一个 `List<RippleData>` 管理活跃涟漪，每帧更新参数、剔除过期的。

```
生成间隔: 600ms
第一道延迟: 进入录音后 200ms（等弧到位再出）
同时最多: 3 道（1800ms 生命期 / 600ms 间隔）

每道涟漪的初始值（生成瞬间从主弧复制）:
  圆心X: 与主弧相同 (cx)
  圆心Y: 与主弧当前圆心Y相同
  半径:  与主弧相同 (R)

每帧更新（t = 此涟漪已存活时间 / 1800ms）:
  圆心Y: 初始值 + 22*sh * t    // 向上飘
  半径:  初始值 + 4*sh * t      // 略微扩大
  alpha: 0.55 * (1-t)           // 渐隐
  线宽:  0.14*sw

渲染: 每道涟漪和主弧一样画弧形描边（无填充、无光晕）
过期: t ≥ 1 时从列表移除
状态切换时不强制清除，让飞行中的涟漪自然消亡

Shader 传参方式: 用固定长度 uniform 数组（最多 3 道），每帧从 C# 写入:
  float4 _Ripples[3];  // xyz = 圆心Y / 半径 / alpha，w = 0 表示该槽位空
```

### 3.5 收回 arc-close

```
时长: 0.45s
缓动: t = elapsed / 0.45, t' = 1 - pow(1-t, 2)

露出量    = lerp(22*sh, 5.5*sh, t')    // 从录音升高位沉到色块静息位
描边alpha = 0.8 * (1-t')
光晕脉冲  = elapsed < 0.35 ? sin(elapsed/0.35 * π) * 0.6 : 0  // 用实际秒数，非归一化 t
```

录音期间已发射的涟漪不强制清除，让它们自然走完生命期淡出。

### 3.6 光晕实现

**不要用后处理高斯模糊。** 在 Shader 中用距离场衰减，一个 pass 搞定：

```hlsl
// 第一步：计算像素到圆周的有符号距离
float2 pixelPos = /* 当前像素的屏幕坐标（左下角原点，像素单位） */;
float2 center = float2(cx, cy);          // 圆心（从 C# 传入）
float dist = length(pixelPos - center) - R; // 正=外侧，负=内侧

// strokeHalf = 描边粗细的一半

// ① 锐利描边：距离在 ±strokeHalf 之内的像素
float strokeMask = smoothstep(strokeHalf + 0.5, strokeHalf - 0.5, abs(dist));

// ② 光晕：从描边边缘向两侧扩散的指数衰减
float edgeDist = max(0.0, abs(dist) - strokeHalf);  // 距描边边缘的距离
float glowFalloff = 1.5 * sw;  // 扩散半宽，约 16px@1080
float glowMask = exp(-edgeDist * edgeDist / (glowFalloff * glowFalloff));

// ③ 合成
float finalAlpha = strokeAlpha * strokeMask + glowAlpha * glowMask * (1.0 - strokeMask);
output.color = float4(baseColor, finalAlpha);
```

要点：
- `edgeDist` 从描边边缘算起，不是从圆周算起，所以描边内部不会被光晕覆盖
- 光晕向内外**两侧**扩散（用 `abs(dist)`），不是只往外
- `(1.0 - strokeMask)` 避免光晕和描边重叠区域过亮
- 性能：纯数学计算，无纹理采样，一个 pass，移动端无压力

> **原型对照说明**：网页原型用 CSS `filter: blur(14px)` 实现光晕，Unity 用上述距离场衰减替代。`glowFalloff = 1.5*sw` 已校准为与 CSS blur(14px) 视觉等效。以原型的实际视觉效果为准。

## 四、上滑色块（填充 · 推进用）

弧顶以下的半透明填充面。弧顶有一条极细亮边。用户全屏上滑推进剧情。

### 4.1 状态参数表

| 状态 | 露出量 | 填充 alpha | 持续时间 |
|---|---|---|---|
| **预告光** | — | — | 1.0s |
| **浮出** | -3sh → 5.5sh | 0 → 0.15 | 1.0s（从 0.6s 开始） |
| **呼吸** | 5.5sh ± 0.75sh | 0.12 ~ 0.18 | 循环 4.0s |
| **跟手** | 5.5sh + 最多 8sh | 0.15 → 0.25 | 实时 |
| **推进** | 从松手位继续上冲 14sh | 渐淡到 0 | 0.5s |

### 4.2 预告光

色块出现前，屏幕底边中央亮起一团扁平椭圆柔光。

```
时长: 1.0s
亮度曲线: pow(sin(t * π), 1.6)

Shader 实现:
  以屏幕底边中点为圆心 (50*sw, 0)
  计算径向距离时，Y 坐标乘以 4（纵向压缩 25% → 横向扁椭圆）
  半径: 50*sw

  float2 center = float2(screenWidth*0.5, 0);
  float2 d = pixelPos - center;
  d.y *= 4.0;  // 纵向压缩
  float r = length(d) / (50*sw);

  alpha 渐变:
    r=0:     pulse * 0.6
    r=0.15:  pulse * 0.35
    r=0.4:   pulse * 0.12
    r=1.0:   0
```

不需要模糊后处理，渐变本身自带柔化。

### 4.3 浮出（色块部分）

```
起始: 预告光开始后 0.6s（与预告光交叠 0.4s，无暗隙）
时长: 1.0s
缓动: t' = 1 - pow(1-t, 2.5)

露出量 = lerp(-3*sh, 5.5*sh, t')  // 起始弧顶在底边以下 3sh（不可见），浮出到 5.5sh
填充alpha = 0.15 * t'
```

### 4.4 呼吸 fill-idle

```
周期: 4.0s, 相对时间计时（同回响弧，保证与浮出结束值衔接）

b = sin(elapsed / 4.0 * 2π)
露出量    = 5.5*sh + 0.75*sh * b
填充alpha = 0.15 * (1 + 0.2*b)    // 0.12 ~ 0.18
```

### 4.5 跟手 fill-swipe

```
输入: 手指向上位移 dy（物理像素，正值=向上）
progress = clamp(dy / 40, 0, 1.3)

露出量增加 = 8*sh * min(1, progress)
填充alpha  = 0.15 + 0.1 * min(1, progress)
```

**松手判定**：
- dy ≥ 40px **或** 速度 ≥ 0.25 px/ms → 推进成功 → fill-commit
- 否则 → progress 在 250ms 内平滑回弹到 0（ease-out cubic: `1 - pow(1-t, 3)`），回到 fill-idle

### 4.6 推进 fill-commit

```
时长: 0.5s
缓动: t' = 1 - pow(1-t, 3)

// 从松手时的实际位置接着上冲，不回弹
起始偏移 = 8*sh * min(1, 松手时的progress)  // progress 已 clamp 到 1，不用 raw 值 1.3
终点偏移 = 14*sh
当前偏移 = lerp(起始, 终点, t')
填充alpha = 松手时的alpha * (1-t')
```

### 4.7 填充渲染

```
填充区域: 弧顶以下 → 屏幕底边以下（封闭路径）

线性渐变（弧顶 → 底边）:
  弧顶:  rgba(255,235,210, alpha)
  中间:  rgba(255,235,210, alpha*0.35)
  底边:  rgba(255,235,210, 0)

弧顶亮边: 0.09*sw 线宽, rgba(255,235,210, min(0.3, alpha*1.2))

混合模式: 正常 alpha 混合（非 Additive）
预告光和色块在 0.6-1.0s 重叠期间自然叠加即可
```

### 4.8 渲染方式

建议用一个全屏 UI `RawImage`（挂在 Screen Space - Overlay Canvas 上）+ 自定义 Material。Shader 在一个 pass 中处理主弧/色块/涟漪/预告光的全部绘制。C# 脚本每帧通过 `Material.SetFloat` / `SetVector` / `SetVectorArray` 传入状态参数。

## 五、新手引导

前 2 次出现，之后永不再出现。引导的 alpha 直接由对应弧/色块的当前 alpha 驱动——**不使用独立的淡入淡出逻辑**，避免时间线错位。

### 5.1 回响弧引导

```
触发: arc-enter / arc-invite / arc-record 状态
蒙层: 屏幕下 1/3（Y < Screen.height/3）
      上沿 5*sh 线性渐变羽化
      alpha = 弧描边alpha * 0.15

文字: arc-enter/invite → "长按说话"
      arc-record → "松手发送"
位置: (屏幕中心X, 16*sh)
alpha = min(0.9, 弧描边alpha*0.55 + 0.45)
字体: 无衬线（对应 Unity TextMeshPro 默认字体或项目指定字体）
字号: 屏幕宽度的 1.3%（约 14px@1080）
字间距: 18% em
```

### 5.2 上滑色块引导

```
触发: fill-enter / fill-idle 状态
形状: 与色块同弧度的填充光带（同圆、同半径 R）
动画: 弧顶从屏幕底边以下升到 66.7*sh 处渐隐（屏幕上 1/3 边界），3.0s 循环
      缓动: t' = 1 - pow(1-t, 2)
      alpha = 色块fillAlpha * 1.0 * (1-t')
      上沿 5*sh 渐变羽化（与回响弧蒙层一致）

文字: "上滑推进"
位置: (屏幕中心X, 25*sh)
alpha = min(0.9, 色块fillAlpha*2.5 + 0.45)  // 跟色块呼吸走，不跟光带走
字体/字号/字间距: 同回响弧引导
```

## 七、状态转移

```
上滑色块:
  fill-enter ─1.6s─→ fill-idle ←─上滑未达阈值─→ fill-idle
                         │
                      上滑成功
                         ↓
                     fill-commit ─0.5s─→ [外部系统决定下一步]

回响弧:
  arc-enter ─1.0s─→ arc-invite ←─短按(<250ms)─→ arc-invite
                        │
                     长按≥250ms
                        ↓
                    arc-record ─松手─→ arc-close ─0.45s─→ [外部系统决定下一步]

特殊: arc-enter 期间长按 → 剩余入场 0.15s 加速完成 → arc-record
```

**外部接口**（C# 暴露给上层系统）：
```csharp
// 上层调用，切换模式
void StartFillMode();    // 进入 fill-enter → fill-idle
void StartArcMode();     // 进入 arc-enter → arc-invite

// 事件回调，通知上层
Action OnSwipeCommit;    // 上滑推进成功
Action OnRecordStart;    // 长按开始录音
Action OnRecordEnd;      // 松手结束录音
Action OnArcCloseEnd;    // 收回动画结束

// 实时输入（上层不需要关心）
void SetSwipeProgress(float totalDy);  // 传入手指从按下点到当前位置的累计向上位移（物理像素）
void ResetTutorial();                  // 重置引导计数（调试用）
```

**状态转换的时间由模块内部管理**：外部只调 `StartFillMode()` / `StartArcMode()` 和接收回调，不需要关心 fill-enter 多久切到 fill-idle——模块内部用协程 / 计时器自动完成所有中间状态的转换。

## 八、色值

所有弧形元素共用一个基色，只变 alpha。

| 用途 | R | G | B | A |
|---|---|---|---|---|
| 基色 | 255 | 235 | 210 | 见各状态 |
| 预告光中心峰值 | 255 | 235 | 210 | 0.6 |
| 引导文字 | 255 | 235 | 210 | 0.75~0.9 |
| 背景 | 7 | 8 | 17 | 1.0 |
